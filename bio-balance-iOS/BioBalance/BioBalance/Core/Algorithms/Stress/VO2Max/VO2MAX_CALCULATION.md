# 心肺能力（VO2 Max）3.0 计算规范

本文是 Mianyu 心肺能力算法的实现合同。心肺能力以 VO2 Max 表示，单位为 `ml/kg/min`。该结果用于长期体能趋势与日常自我管理，不是实验室心肺运动试验，也不构成医疗诊断。

## 实现边界

```text
Core/Algorithms/Stress/VO2Max/
├── Domain/VO2MaxModels.swift
├── Engine/VO2MaxRules.swift
├── Engine/VO2MaxEngine.swift
├── Persistence/VO2MaxAssessmentStore.swift
└── VO2MAX_CALCULATION.md
```

| 文件 | 职责 |
| --- | --- |
| `Domain/VO2MaxModels.swift` | 输入、输出、来源、趋势、分级和解释模型 |
| `Engine/VO2MaxRules.swift` | 纯规则、证据门槛、权重、分级、置信度、平滑与趋势 |
| `Engine/VO2MaxEngine.swift` | HealthKit 数据编排、特征构建、按日和按训练评估 |
| `Persistence/VO2MaxAssessmentStore.swift` | 3.1 日评估缓存 |

页面不得复制 VO2 Max 公式、阈值或趋势规则。Watch、Widget 和 Complication 只消费 iPhone 同步结果。

VO2 Max 是低频心肺能力指标，不要求每天产生新值。今日页优先展示当天评估；当天没有新证据时，可继续展示最近 30 天内最新的有效评估，并保留原始评估日期。超过 30 天或只有未来记录时显示等待新样本，不复制数值生成虚假的每日记录。

## 真值优先级

1. HealthKit 当日 `vo2Max` 样本是最高优先级真值。
2. 本地引擎可以给真实样本补充来源解释，但不得修改真实数值。
3. 没有有效真实样本时，才允许生成本地估算。
4. 没有最低心肺证据时返回空值，不用固定中性分填补。

有效真实样本必须是有限数，且位于 `10...90 ml/kg/min`。超出范围的值按无效样本处理。

来源含义：

| 来源 | 数值 | 解释 |
| --- | --- | --- |
| `healthKitActual` | HealthKit 原值，仅保留一位小数 | 没有额外解释上下文 |
| `engineBlended` | 仍是 HealthKit 原值 | 只混合本地解释，不混合数值 |
| `engineEstimated` | 本地估算值 | HealthKit 当日没有有效 VO2 Max |

## 输入与历史窗口

引擎读取：

- 年龄、生理性别、身高、体重
- HealthKit VO2 Max
- 静息心率与夜间 HRV
- 夜间平均心率、睡眠评分
- 步行速度与步行平均心率
- 跑步、户外步行和徒步训练
- 训练后 1 分钟心率恢复

按日评估会比展示窗口额外读取 30 天历史，用于构建个人基线。基线只使用目标日之前的数据，不能包含当天，避免当前样本同时出现在分子和基线中。

- 静息心率：此前最多 30 个有效日，至少 3 个样本，取中位数。
- 夜间 HRV：此前最多 14 个有效日，至少 3 个样本，取中位数。
- 步行效率：此前最多 14 个同时具备速度与步行心率的日期，至少 3 个样本。
- 跑步效率：此前 28 天合格跑步，至少 2 次。

## 样本质量

步行训练至少满足 `1 km` 或 `12 min`。HealthKit 的日步行聚合没有伪造距离和时长，按日聚合样本单独通过质量入口。只有步行速度时允许生成保守估算；步行平均心率与静息心率可选，二者同时有效时才计算心率成本和个人步行效率，并提高样本质量贡献。

跑步样本的最低有效性门槛为：

- 时长至少 `5 min`
- 距离至少 `0.5 km`

平均心率和配速用于计算跑步效率，因此必须存在、为有限数且大于 0，但不设置固定强度或速度区间。不接受无穷值、NaN 或非正数输入。

训练评估只关联训练开始前 `30 min` 到训练结束后 `2 h` 内的 HealthKit VO2 Max 样本，并优先选择最接近训练结束时间的有效样本。同一天但不在该窗口内的真实样本不能复制给这次训练。

## 五个分量

每个有效分量映射到 `0...100`。缺失分量退出加权，不补 0 或 50。

| 分量 | 标称权重 | 主要含义 |
| --- | ---: | --- |
| 静息心率 | 0.20 | 当前静息心率相对个人基线 |
| 夜间 HRV | 0.15 | 当前夜间 HRV 相对个人基线 |
| 步行能力 | 0.20 | 优先使用心率成本下的步行速度，缺少心率时保守使用步行速度 |
| 跑步效率 | 0.30 | 配速、平均心率与历史效率 |
| 恢复 | 0.15 | 睡眠、HRV、夜间心率和训练后恢复 |

组合分数按实际可用权重重新归一化：

```text
componentScore = sum(score_i * weight_i) / sum(availableWeight_i)
```

最低证据满足任意一项才允许输出：

```text
有效 HealthKit VO2 Max
或 合格步行速度/效率
或 合格跑步效率
或 静息心率 +（HRV 或恢复）
```

仅有睡眠、夜间心率或恢复信息时不能推导心肺能力。只有步行速度时可以输出低置信度估算，不伪造缺失的心率输入。

## 估算映射

无真实样本时，综合分先映射到 VO2 Max：

```text
base = 22 + componentScore * 0.28
estimate = base
         + sexAdjustment
         - ageAdjustment
         + bodySizeAdjustment
         + runningAdjustment
         + walkingAdjustment
```

年龄、性别和体型只做有限修正；运动效率仍是主要动态信息。最终估算限制为 `18...65 ml/kg/min` 并保留一位小数。

这是一套消费级传感器启发式模型，不应描述为 Apple 官方算法或医学测量。

## 置信度

置信度由来源、覆盖度和样本质量组成：

```text
confidence = source * 0.45 + coverage * 0.30 + quality * 0.25
```

- 有效 HealthKit 真值的最终置信度下限为 `90`，上限为 `95`。
- 本地估算最高为 `85`。
- 跑步来源权重高于步行；只有静息心率与恢复信号时更保守。
- 训练样本数最多按 4 次计入质量，避免大量低质量记录无限抬高置信度。

置信度表达输入依据完整度，不表示医学准确率。

## 平滑与趋势

真实值和 `engineBlended` 值不做数值平滑。仅当前后两天都是连续的 `engineEstimated` 时限制日变化，每天最多 `±0.7 ml/kg/min`；真实来源切换或日期断档会重置平滑。所有今日页调用至少使用同一段 31 天计算上下文，避免 1 天、30 天与 31 天查询得到不同的目标日结果。

趋势按真实日期划分最近 7 天和此前 7 天：

- 两个窗口都至少需要 3 个置信度不低于 50 的样本。
- 有意义变化阈值为 `max(0.8, 前一窗口均值 * 2%)`。
- 达到正向阈值为 `improving`，达到负向阈值为 `declining`，否则为 `stable`。
- 样本不足时固定为 `stable`，页面应结合置信度解释为“暂未形成趋势”。

## 体能分级

分级同时考虑年龄段与生理性别，包含 `<30`、`30...39`、`40...49`、`50...59`、`60+` 五档。支持中文和英文性别值；性别未知时使用男女阈值中点，不默认归入任何一方。

分级只用于同年龄段下的产品解释，不应用于疾病风险判断。

## 缓存与版本

- 当前规则版本：`3.1`
- 当前缓存键：`vo2MaxDailyAssessment.v3_1`
- 旧 2.x 缓存不会被 3.0 读取，避免不同规则结果混入同一趋势。
- 修改最低证据、权重、映射、分级、置信度、平滑或趋势阈值时必须升级规则版本与缓存键。

## 测试合同

`BioBalanceTests/Stress/VO2Max/VO2MaxRulesTests.swift` 至少覆盖：

- 无心肺锚点时不输出估算。
- 缺失分量动态重归一化。
- 真实 HealthKit 数值不参与数值混合。
- 无效真实样本回退到有界估算。
- 真实样本置信度下限。
- 未知性别使用中性阈值。
- 只平滑估算值。
- 趋势使用两个自然日期窗口且样本不足时保持稳定。
- 日步行聚合不依赖伪造的距离或时长。
- 步行个人基线方向、跑步异常输入拒绝和恢复信号方向正确。

## 局限与声明

药物、感染、海拔、温度、佩戴质量、心率采样密度、训练类型和个体差异都会影响结果。本地估算只适合观察数周方向；单次变化不代表心肺能力在一天内发生同等幅度改变。出现胸痛、明显气短、晕厥或其他不适时，应寻求专业医疗帮助，不应依赖本算法做决定。
