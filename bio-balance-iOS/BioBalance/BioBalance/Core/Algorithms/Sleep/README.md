# 睡眠算法模块

`Core/Algorithms/Sleep` 负责睡眠会话评分、环境音频推断、晚睡恢复建议和长期环境趋势。模块中的计算应保持确定性；传感器读取、权限请求、UI 和网络同步由模块外部完成。

> 本模块提供消费级健康趋势参考，不用于诊断睡眠呼吸暂停或其他睡眠疾病。持续鼾声、呼吸中断或明显日间嗜睡应由专业医疗人员评估。

## 数据边界

```text
HealthKit / 麦克风 / 用户设置
              ↓
       适配与输入归一化
              ↓
       Sleep 算法（本目录）
              ↓
 summary / events / plan / trend
              ↓
 ViewModel、App Group、Watch、Widget
```

- 时间统一使用 `Date`，时区和自然日边界由调用方通过 `Calendar` 明确传入或在会话开始时固定。
- 分数使用闭区间 `0...100`；置信度使用闭区间 `0...1`。
- `nil` 表示没有观测依据；测量值 `0` 不等同于缺失。
- 音频只在本地提取特征。除非用户明确同意，不持久化或上传原始 PCM。
- 历史结果必须连同算法版本存储。版本变化后不得直接混合计算趋势。

## 睡眠评分 3.3

当前算法版本为 `sleep-scoring-3.3.0`。睡眠会话使用可获得的时长、连续性、潜伏期、实测阶段、规律性和环境干扰证据计算综合分。缺失分量退出加权，剩余权重重新归一化；不得以 `0` 或固定中性分填补。输出置信度反映证据覆盖和质量，并不表示医学准确率。

3.1 在 3.0 公式不变的基础上补充时间证据适配：有效的主睡眠区间提供 TIB；带时间戳的 Awake 片段先限制在首次入睡与最后睡眠之间，再做区间并集得到 WASO。区间短于观测睡眠时长、超过 24 小时或时间顺序无效时，TIB/WASO 一并退出并回退到派生连续性。当前区间模型没有保存显式 `inBed` 来源，因此不从它推断入睡潜伏期。

3.2 接入历史规律性证据：只使用当前会话之前的主睡眠开始时间，以中午为睡眠日分界去重，取最近最多 7 晚且至少需要 3 晚。基准选择使样本间 24 小时圆周距离总和最小的实际观测时刻（圆周 medoid），当晚偏差取最短圆周距离，因此 23:50 与 00:10 相差 20 分钟而不是 23 小时 40 分钟。该分量由多晚实测时间戳确定性推导，证据等级为 `derived`；历史不足时规律性保持缺失。

3.3 修正鼾声干扰证据：不再用最后一个 RMS 窗口外推整夜，也不再生成固定间隔的虚构片段。候选窗口按真实采样时间排序，间隔不超过 3 秒的窗口合并为事件；事件至少需要 2 秒直接活动证据。没有合格事件时输出 `.empty`，清醒次数本身不会制造鼾声干扰分。

| 分量 | 权重 | 证据要求 |
| --- | ---: | --- |
| 时长 | 0.25 | 有效时长和睡眠目标，必需 |
| 连续性 | 0.25 | TIB/WASO 实测，或派生备用连续性 |
| 潜伏期 | 0.10 | 有效实测值 |
| 阶段分布 | 0.15 | Deep 与 REM 都有效且阶段来源为 measured |
| 规律性 | 0.20 | 至少 3 晚历史主睡眠开始时间生成的圆周偏差（derived） |
| 干扰 | 0.05 | 实际运行过音频/事件检测 |

```text
score = round(Σ(wᵢ × sᵢ) / Σwᵢ)，仅对可用分量求和
confidence = clamp(Σ(wᵢ × evidenceReliabilityᵢ), 0, 1)
```

证据可靠系数为 measured `1.00`、derived `0.65`、inferred `0.35`。总分要求时长有效且可用权重至少为 `0.50`；否则返回 unavailable。推断的阶段分布只用于降级展示，不进入阶段分。

评分实现必须满足以下不变量：

1. 输出分数始终位于 `0...100`。
2. 相同输入、日历和算法版本得到相同结果。
3. 增加缺失项不会提高证据覆盖率。
4. 无有效会话或有效样本时返回 unavailable，而不是伪造分数。
5. 各阶段时长之和不得超过归一化后的会话时长。
6. 公式、权重、阈值或缺失语义变化后必须升级 `algorithmVersion`。

### 阶段归一化

- HealthKit 返回同一阶段的多段样本时，先累加所有非负时长，不只读取第一段。
- 已分类阶段总时长小于会话时长时，未分类部分归入浅睡，不凭空增加深睡或 REM。
- 已分类阶段总时长超过会话时长时，按比例缩放三类阶段，保留原始构成比例。
- 没有阶段样本时使用 Deep 22%、Light 54%、REM 24% 的基线分布；短睡和小睡不设置会超过总时长的固定分钟下限。

### 确定性时钟

`SleepScoringEngine.makeSummary` 的 `now` 是算法评估时间，`calendar` 定义自然日和时区。两者都可注入，以便历史重放和测试。摘要的 `createdAt`、`updatedAt` 与洞察的 `generatedAt` 必须来自同一个 `now`，算法内部不得再次读取系统时间。

## 音频推断

当前生产管线按约 1 秒窗口提取 RMS 与过零率，并先把窗口区分为安静、疑似语音、持续噪声和活动声。只有超过活动阈值的“活动声”进入疑似鼾声聚合；疑似语音和持续噪声不进入。相邻候选按真实时间戳合并，最多允许 3 秒间隔，并要求至少 2 秒直接候选证据，孤立爆音不会形成事件。片段起止时间、活动时长、频次和直方图均来自保留下来的窗口，不从整夜时长推算。

这仍是消费级的“疑似鼾声事件”启发式检测，不是经过鼾声标注数据训练和验证的专用分类器。可选 VAD 只能帮助排除语音，不能单独证明剩余声音就是鼾声。后续若接入梅尔频谱/MFCC 专用模型，必须独立做说话、空调、床品摩擦、远近距离和不同设备的回放验证。

环境噪声、说话、床品摩擦和设备距离都会产生混淆。展示层必须使用“疑似鼾声”或“鼾声趋势”，不得表述为疾病诊断。

## 降级策略

| 场景 | 行为 |
| --- | --- |
| HealthKit 权限缺失 | 保留可用来源，降低置信度并说明缺失项 |
| 麦克风未授权 | 关闭音频分量，不影响基础睡眠会话 |
| Watch 数据延迟 | 延迟补算或保持 unavailable，不以设备端重算覆盖 iPhone 结果 |
| 会话不足一晚 | 可展示当晚摘要，不生成长期趋势 |
| 样本时间异常 | 丢弃负时长、未来或无法归属会话的样本 |

## 测试合同

新增或修改公式时，至少覆盖：

- 正常睡眠、短睡和跨午夜会话；
- 空样本、部分权限和延迟到达样本；
- 分数及置信度的上下界；
- `0` 与 `nil` 的不同语义；
- 音频窗口边界、事件合并和噪声误报；
- 夏令时、时区变化及旅行场景；
- 算法版本升级后的历史隔离与解码兼容。

## 维护约定

公式、阈值或权重变化时，应在同一次变更中更新实现、测试和本文档，并递增对应算法版本。UI 文案和颜色映射不应进入计算引擎；需要展示解释时，通过明确的 Presentation 类型转换。
