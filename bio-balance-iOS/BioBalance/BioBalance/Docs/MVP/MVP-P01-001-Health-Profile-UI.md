# MVP-P01-001 健康档案 UI 与一级页面衔接

## 1. 文档信息

- 分类：`P01 健康档案与长期画像`
- 优先级：P1
- 首发端：iPhone
- 状态：已完成可读性第二阶段
- 数据位置：复用现有 `HealthProfileSummary`，不新增持久化或云字段

## 2. 用户问题

原健康档案首屏仪表占用空间较大，当前状态、数据可信度和重点维度需要较多滚动才能形成整体认识；今日页中的长期档案入口也混在身体信号卡组内，健康页的阅读顺序偏向功能堆叠。

## 3. MVP 范围

1. 健康档案首屏改为紧凑概览，直接展示时间范围、档案状态、成长指数或依据质量。
2. 同屏展示数据可信度、核心数据覆盖和观察范围。
3. 增加“一眼看懂”区，按风险优先级展示最多三个有分数的健康维度。
4. 保留 AI 解读、重新同步、行动建议、全部维度、变化、长期画像、档案依据和主观补充入口。
5. 今日页将长期健康档案提升为独立区块，放在身体信号之前。
6. 健康页调整为长期档案、当前重点、趋势与报告、快捷记录、今日健身、能力地图、好友陪伴的阅读顺序。
7. 健康档案页面的文字切换、展开和状态变化不添加动画。

### 3.1 可读性第二阶段

1. 正文说明字号不低于 14pt，辅助说明不低于 12pt，极少数胶囊标签不低于 11pt。
2. 首屏三项数据事实由三列小卡改为纵向信息行，避免标题和值同时被压缩。
3. “一眼看懂”由三列数字宫格改为纵向摘要卡，完整展示维度名称、当前趋势与分数。
4. “本周照顾重点”把行动内容和判断依据分成两个层级，不再合并成同一段小字。
5. 维度、变化、长期画像和档案依据统一提高标题、正文、状态文字的字号与行距。
6. 卡片内边距和卡片间距适度增加，保持一张卡只表达一个主要问题。
7. 继续支持大字号、VoiceOver 和紧凑宽度，不通过截断长文案换取整齐。

## 4. 数据与隐私边界

- UI 仅消费已有 `HealthProfileSummary` 和本机派生 `dataQuality`。
- 不新增 HealthKit 查询、SwiftData 模型、CloudKit record type 或 App Group 投影。
- AI 入口继续只传递现有聚合摘要，不增加原始样本或自由文本字段。
- 成长指数和维度分数不描述为诊断、风险概率或治疗效果。

## 5. 页面结构

### 健康档案

1. 紧凑概览 Hero。
2. 三项关键维度快照。
3. 本周照顾重点。
4. 全部健康维度。
5. 近期变化与长期画像。
6. 档案依据与体感补充。
7. 健康说明与更新时间。

### 一级页面衔接

- 今日：AI 今日解读 → 长期健康 → 身体信号。
- 健康：长期档案 → 当前重点 → 趋势/报告 → 记录与健康能力。

## 6. 不做

- 不修改健康档案评分算法或数据缺失规则。
- 不新增独立健康风险等级。
- 不因 UI 重排改变用户的模块显示偏好。
- 不把健康档案改成医疗档案或电子病历。

## 7. 验收标准

1. 建立中、有数据和无数据状态均可正常显示。
2. 7、30、90 天范围切换继续使用现有加载流程。
3. AI、同步、权限、今日记录和各详情导航保持可用。
4. 三项快照只展示真实存在的维度分数。
5. VoiceOver 能读出分数、状态、覆盖和维度快照。
6. iPhone 紧凑与扩展布局均无水平溢出。
7. 页面用户可见文字不添加动效。
8. 关键正文无需缩放即可阅读；三项快照和行动依据不出现 9–10pt 小字。
9. 在紧凑宽度下，维度名称、行动标题和依据文案均可完整换行。
